Chapter 3: A Second Hidden Layer

Learning Objectives

  • Recognize underfitting: a loss that stays above the noise level no matter how long we train
  • Describe two options for an underfit network: more nodes in the hidden layer, and a second hidden layer
  • Explain what a second-layer node sees, and how blocks made of blocks arise
  • Compare the two options by counting parameters

Motivation

  • In chapter 2, gradient descent found the three blocks behind our noisy data. The function had three steps and the network had three blocks: a perfect match.
  • But what happens when the function has more steps than the network has blocks? We generated new data to find out (again from a recipe we are keeping hidden, again with a little noise).
  • The plan: watch the chapter 2 network fail, then try two options, and count the parameters of each.

1. A Harder Function

  • The gray points below follow a function with four steps (down, up, down, up: two valleys with a hill between them), plus the usual noise.
  • The network is exactly the one from chapter 2: three sigmoid blocks and an output bias, 10 parameters. Press train and let gradient descent run.
  • Or try the sliders yourself first. Each block gives one step, and the data has four, so however you place three blocks, one piece of the function must be given up.

  • Training runs its full 400,000 epochs and the loss gets stuck well above the loss of the generating parameters. No amount of extra training helps. The problem is not the optimizer; the network simply cannot represent the function.
  • This situation is called underfitting: the model does not have enough flexibility to match the pattern in the data. Watch the replay: gradient descent does its best and then ends up with a compromise (typically it fits one valley properly and puts a flat line through the rest).

2. Option One: More Nodes in the Hidden Layer

  • The first option is the obvious one: if three blocks are not enough, use four. Four steps in the data, four blocks in the network, a 1 → 4 → 1 architecture.
  • No sliders this time: gradient descent does the fitting, and we watch.
loss (MSE):  · epoch: 0  · loss of the generating parameters:
  • The loss now goes all the way down to the noise level: four blocks can build four steps.
  • Parameter count: 3 per block plus the output bias, so $4 \times 3 + 1 = $ 13 (chapter 2's network had 10).
  • Note the price structure: every extra step costs a full extra block, 3 more parameters, every time. A function with eight steps would need eight blocks (25 parameters), one with twenty steps twenty blocks. The cost grows with the size of the pattern, even when the pattern is the same shape over and over.

3. Option Two: A Second Hidden Layer

  • Here is the other option. Instead of making the one hidden layer wider, we put a second hidden layer between it and the output: a 1 → 2 → 2 → 1 architecture.
  • The model, written out (the second layer's parameters are $u_{kj}$ and $d_k$):
$$h_j = \phi(w_j x + b_j), \qquad a_k = \phi(u_{k1} h_1 + u_{k2} h_2 + d_k), \qquad \hat{y} = v_1 a_1 + v_2 a_2 + c$$
  • The key point, and the whole reason this chapter exists: the second layer's nodes never see $x$. Their inputs are $h_1$ and $h_2$, the outputs of the first layer. A first-layer block is a step in $x$; a second-layer block is a step in whatever the first layer built.
  • How that builds a W shape with only two nodes per layer:
    1. The first layer makes two steps, one rising on the left, one rising on the right. With weights $u_{k1} = +u,\; u_{k2} = -u$ a second-layer node receives their difference, and the difference of those two steps is a bump: near 1 in the middle of the plot, near 0 at both ends.
    2. A second-layer node is then a step in that bump: it turns on where the bump is high enough. A low threshold turns on over a wide region; a higher threshold over a narrow one. (In the plot below: the gold and plum curves.)
    3. The output takes the wide region with a minus sign and the narrow one with a plus sign, and a W appears: down at the edges of the bump, back up in the middle.
  • Both valleys of the W come from the same bump: one is its left side, the other its right side. The pattern is built once, then used twice. That is what depth gives us.
loss (MSE):  · epoch: 0  · loss of the generating parameters:
  • In the plot, the crimson and green curves are the first layer's steps $h_1, h_2$ (drawn raw, between 0 and 1, because that is what the second layer sees). The gold and plum curves are the second layer's contributions $v_1 a_1$ and $v_2 a_2$, scaled the way they enter the sum, and the purple curve is their sum plus $c$.
  • Parameter count: 4 in the first layer (2 weights, 2 biases), 6 in the second (4 weights, 2 biases), 3 in the output (2 weights, 1 bias): 13 in total. The same price as the wide network.
  • After training, press reveal our recipe. The parameters jump to the ones we used to generate the data, and the purple curve barely moves. Gradient descent found a different recipe for the same function: not the parameter values we used, but a curve we cannot tell apart from them. With depth there is more than one way to build a shape, and only the output matters.
  • Note that we gave this network a helpful starting point (large weights in the second layer). Start the weights too small and gradient descent gets stuck before the W appears. Deeper networks are more flexible but also harder to train; we will come back to this when we discuss how deep networks are trained.

  • On this function the two options cost exactly the same. The difference is strategy: the wide network used a full block for each of the four steps; the deep network built one bump and got both valleys out of it.
  • Reuse is what scales. But let's be clear about what this example did and did not show: it showed that depth can reuse (both valleys came from one bump); it did not show depth winning the count, since the two options came out equal here. The win is an argument about bigger patterns: if the pattern in the function showed up again (eight steps), the wide network would need eight blocks, paying full price each time, while the deep network can keep reusing what its first layer builds. The gap grows with the size of the pattern.
  • The fair summary: depth gives reuse, and the price is harder training (recall the starting-point note above). For a function as simple as chapter 2's, a single wide-enough hidden layer is a perfectly good choice.
  • This idea, learn a shape once, reuse it everywhere, is the heart of deep learning, and we will see it again in its most famous form when we get to images: convolutional networks reuse the same small pattern at every position of a picture.

(Optional) The Same Network in Code

The 1 → 2 → 2 → 1 network in plain numpy. The forward pass is two matrix products with a sigmoid after each, plus the output layer:

import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

w = np.array([1.0, 1.0]);   b = np.array([2.0, -2.0])                 # first hidden layer
U = np.array([[4.0, -4.0],
              [4.0, -4.0]]); d = np.array([-1.4, -2.9])               # second hidden layer
v = np.array([-1.0, 1.5]);  c = 0.0                                   # output layer

def forward(x):
    H = sigmoid(np.outer(x, w) + b)     # first layer,  shape (n, 2)
    A = sigmoid(H @ U.T + d)            # second layer, shape (n, 2)
    return A @ v + c

And the training loop (predict, compare, adjust), where the adjustment is now passed backward through both layers:

lr = 0.25
n = len(x)
for epoch in range(400_000):
    H = sigmoid(np.outer(x, w) + b)
    A = sigmoid(H @ U.T + d)
    c = np.mean(y - A @ v)
    err = (A @ v + c) - y
    # adjust every parameter, output layer back to the first
    gA = np.outer(err, v) * A * (1 - A)
    gH = (gA @ U) * H * (1 - H)
    v -= lr * 2/n * A.T @ err
    U -= lr * 2/n * gA.T @ H;   d -= lr * 2/n * gA.sum(axis=0)
    w -= lr * 2/n * gH.T @ x;   b -= lr * 2/n * gH.sum(axis=0)

In PyTorch, adding a layer is one more line in the stack:

import torch
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(1, 2), nn.Sigmoid(),      # first hidden layer
    nn.Linear(2, 2), nn.Sigmoid(),      # second hidden layer
    nn.Linear(2, 1),                    # output layer
)
criterion = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.25)

for epoch in range(400_000):
    loss = criterion(model(X).flatten(), y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
  • As in chapter 2, our page sets the output bias $c$ analytically instead of adjusting it by gradient, and PyTorch starts from random parameters rather than our chosen starting point, so its path (and possibly its final recipe) will differ.

Chapter Highlights

  1. When the function has more steps than the network has blocks, the loss gets stuck above the noise level and no amount of training helps. This is underfitting.
  2. Option one: more nodes in the same layer. Each new block adds one step and 3 parameters, paying full price for every piece of the pattern.
  3. Option two: a second hidden layer. Its nodes take the first layer's outputs as inputs, so they build steps out of shapes instead of steps out of $x$.
  4. Both options cost 13 parameters here; the deep one built a single bump and used it for both valleys. Reuse is why depth scales better when the same shape shows up again and again (an argument about bigger patterns; on this one the two costs came out equal).
  5. With depth, different parameter settings can produce the same function. Gradient descent found a different recipe than the one we used, and that is fine: only the output matters.
