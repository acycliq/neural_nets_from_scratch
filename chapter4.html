Chapter 4: Classification with Softmax

Learning Objectives

  • Recognize a classification problem: the target is a class, not a number
  • Explain how softmax turns a set of scores into probabilities
  • Explain why the loss for probabilities is cross-entropy, not MSE
  • Read a decision-region plot and the probability triangle
  • Build a curved decision boundary out of the same hidden nodes as before

Motivation

  • So far our networks predicted a number: for every $x$, a $\hat{y}$. But many questions ask for a choice: which of three classes does this point belong to?
  • Note that the machine barely changes. The hidden layers are the lego blocks we already know. What changes is the output (three scores instead of one number) and the loss (a new way to measure being wrong).
  • The plan: meet the new data, meet softmax and cross-entropy, train the smallest possible classifier, and watch it learn in two plots at once.

1. From a Number to a Choice

  • Our new data: each point has two features $(x_1, x_2)$, and a label that is one of three classes. The two features are what we plot: $x_1$ is the point's horizontal position and $x_2$ its vertical position, so the plane below is the space of features. (In a real problem the features would be two measurements of the thing being classified, and with more than two features there would be no plot to draw, but the network would not care.) We generated the points from three overlapping clusters (one cluster per class), so some points sit among points of a different class: no boundary can get everything right, exactly like the noise in our regression chapters.
  • How do we write the target? Not as the number 1, 2, or 3 (class 3 is not "bigger" than class 1). We use a one-hot vector: class 2 becomes $(0, 1, 0)$: all the probability on class 2, none on the others.
  • So the network should output three numbers that behave like probabilities. That is the job of the next section.

2. Scores into Probabilities: Softmax

  • The network's output layer now has three nodes, one score $z_k$ per class. Scores can be any numbers at all. To turn them into probabilities we use softmax:
$$p_k = \frac{e^{z_k}}{e^{z_1} + e^{z_2} + e^{z_3}}$$
  • Three properties, all visible in the demo below:
    1. every $p_k$ is positive and they sum to 1 (so they behave like probabilities);
    2. the biggest score gets the biggest probability, and the bigger the gap between scores, the more confident the result;
    3. adding the same amount to every score changes nothing (press the button and watch the bars stay put): only the differences between scores matter.

3. The Loss: Cross-Entropy

  • We need a loss built for probabilities. The one used everywhere is cross-entropy: look up the probability the model gave to the true class, and take the negative log:
$$\mathcal{L} = -\log(p_{\text{true class}})$$
  • Why not MSE on the probabilities? Because confidence should matter. Giving the true class probability 0.01 is much worse than giving it 0.4, and cross-entropy makes the difference count:

  • As in the regression chapters, we will compare the trained loss against the loss of the generating recipe (the true cluster probabilities): with overlapping classes even the perfect recipe cannot reach zero.

4. Training a Linear Classifier

  • The smallest possible classifier: each class scores a point with a plain linear function, and softmax turns the three scores into probabilities.
$$z_k = w_{k1} x_1 + w_{k2} x_2 + b_k, \qquad p = \text{softmax}(z)$$
  • Parameter count: 3 classes × (2 weights + 1 bias) = 9 parameters. No hidden layer at all: this is the classification version of chapter 1's linear regression.
  • The diagram in the panel is the machine itself: the two features and the constant 1 feed three score nodes (colored by class), and the shared softmax box turns the three scores into probabilities. The numbers on the connections are the 9 parameters, and they update as training runs.
  • Gradient descent adjusts the parameters to make the average cross-entropy small. Two plots below, updated together:
    • Left, the map: the data on its own ground, with the background colored by the model's current choice in each region. The lines where the color changes are the decision boundaries; for this linear model they are straight.
    • Right, the triangle: every point drawn at its three predicted probabilities. The corners are the certain answers, the center is complete uncertainty $(\tfrac13, \tfrac13, \tfrac13)$. A trained point should sit near the corner of its own color.
  • Press train and watch both: the boundaries move into place on the map while the points move out of the uncertain center toward their corners. Then drag the replay slider. Points that sit between two corners are the ones in the overlap: the model spreads its probability between two classes, and it should.

  • The trained loss ends a little below the generating recipe's loss, and the accuracy about matches it. Recall chapter 2: on the points we trained on, fitting some of the noise is always possible. The recipe's numbers are the right target, not a record to beat.
  • (Optional) Question: the logic behind softmax is that its inputs are in log-space: it maps log-probabilities to probabilities. But our scores are just weighted sums of the point's coordinates. Nothing about $w_{k1} x_1 + w_{k2} x_2 + b_k$ says "log-probability"; these are plain numbers built from plain coordinates. What gives us the right to put them through softmax?
  • Answer: using softmax is the claim. The model does not discover that the scores are log-probabilities; it declares them to be: the log-probability of each class is assumed to be a linear function of the features, and training then finds the best such function, the same way chapter 1 assumed a line and least squares found the best one. And for this dataset the claim happens to be exactly right. The clusters are equally spread, so Bayes' rule gives $$p(\text{class } k \mid x) \propto e^{-\|x - \mu_k\|^2 / 2\sigma^2},$$ where $\mu_k$ is the center of cluster $k$. Expand the square: the $\|x\|^2$ part is the same for every class, and softmax ignores anything shared by all the scores (property 3 from the demo above), so what remains of the log-probability is $$z_k = \frac{\mu_k}{\sigma^2} \cdot x - \frac{\|\mu_k\|^2}{2\sigma^2},$$ a weighted sum of the features, with the weights pointing at the cluster centers. The generating recipe is itself a member of our model family, and that is why training can get all the way down to its loss.
  • When the classes are not shaped like this, linear scores are the wrong claim, and the next section shows exactly that.

5. A Curved Boundary Needs Hidden Nodes

  • Straight boundaries are not always enough. In the data below, one class sits inside a ring of another: no straight line separates them.
  • The answer is chapter 1's move, unchanged: put a hidden layer before the output. Each hidden node is the same block as always, except its input is now a direction in the plane: the node computes $\phi(w_1 x_1 + w_2 x_2 + b)$, a smooth step that turns on across a line. Five such steps, combined by the output layer, can bend a boundary into a loop.
  • Architecture 2 → 5 → 3: parameter count $5 \times 3 + 3 \times 6 = $ 15 + 18 = 33 parameters (each hidden node has 2 weights and 1 bias; each output node has 5 weights and 1 bias).
  • These classes do not overlap, so this time there is nothing to be uncertain about: the loss can go all the way toward zero and the accuracy to 100%.
  • With 33 parameters, printing every value on the diagram would be too much. Instead all connections share one color, and the thickness of a line follows the size of its weight as training runs. Put the mouse on a line to see its exact value.

  • Watch the replay closely: the boundary starts nearly straight, then bends, until it forms a loop around the center class. The hidden nodes are doing for the boundary what they did for curves in chapters 1 to 3: building a shape out of simple steps.

(Optional) The Same Classifier in Code

The linear softmax classifier of section 4 in plain numpy (X has one row per point, y holds the class of each point as 0, 1 or 2):

import numpy as np

def softmax(Z):
    E = np.exp(Z - Z.max(axis=1, keepdims=True))
    return E / E.sum(axis=1, keepdims=True)

W = np.zeros((3, 2)); b = np.zeros(3)
onehot = np.eye(3)[y]

lr = 0.5
n = len(y)
for epoch in range(50_000):
    P = softmax(X @ W.T + b)
    G = (P - onehot) / n          # the gradient of cross-entropy through softmax
    W -= lr * G.T @ X
    b -= lr * G.sum(axis=0)

loss = -np.mean(np.log(P[np.arange(n), y]))
accuracy = np.mean(P.argmax(axis=1) == y)
  • The line worth a close look: the gradient of cross-entropy through softmax is just $p - y_{\text{one-hot}}$, the predicted probabilities minus the target ones. Predict, compare, adjust, in its simplest form.

In PyTorch:

import torch
import torch.nn as nn

model = nn.Linear(2, 3)                  # three scores from two features
criterion = nn.CrossEntropyLoss()        # softmax + cross-entropy in one
optimizer = torch.optim.SGD(model.parameters(), lr=0.5)

for epoch in range(50_000):
    loss = criterion(model(X), y)        # X: float features, y: class numbers
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
  • Note that nn.CrossEntropyLoss expects the raw scores, not probabilities: it applies softmax itself. Passing it probabilities instead is a common error.

Chapter Highlights

  1. Classification changes the output and the loss, not the machine: three scores instead of one number, cross-entropy instead of MSE. The hidden layers are unchanged.
  2. Softmax turns scores into probabilities: positive, summing to 1, and only the differences between scores matter.
  3. Cross-entropy reads the probability given to the true class and takes $-\log$: being confident about the wrong class costs the most.
  4. With overlapping classes, the generating recipe's loss and accuracy are the right targets; a trained model that does better on the training points is fitting noise.
  5. Straight boundaries come from linear scores (9 parameters here); curved boundaries come from the same hidden blocks as always, now stepping across lines in the plane (33 parameters here).
