Chapter 2: Non-linear Regression with Gradient Descent

Learning Objectives

  • Approximate a non-linear function as a sum of sigmoid lego blocks
  • Explain the role of each block's location, slope, and height in shaping the sum
  • Describe the gradient descent loop: predict, compare, adjust
  • Explain what an epoch is, and watch the loss fall as training runs

Motivation

  • Recall from chapter 1 that our data followed a straight line. We didn't really need a neural network for that (least squares solves it in one shot).
  • But most functions we care about are not straight lines. Can our lego blocks handle non-linear data? Let's find out!
  • The plan: first we'll fit non-linear data by hand, using three sigmoid blocks. Then we'll hand the same job to gradient descent and watch it adjust the sliders automatically.

1. A Non-linear Function

  • To be clear: we generated the gray data points below ourselves, by evaluating a sum of exactly three sigmoid blocks plus a constant and adding a little random noise. (We are not revealing the parameter values yet.)
  • Before we bring in any blocks, let's record your first guess. Press and drag across the plot below to draw the function you think generated these points. Once gradient descent has done its job later on, we will compare its answer with yours.

  • Each hidden node applies an activation function $\phi$; here we use the sigmoid, $\phi(z) = \frac{1}{1 + e^{-z}}$. A sigmoid block is a smooth step: $v \cdot \phi(w x + b)$, or in other words $v \cdot \phi\big(w\,(x - \text{location})\big)$ (the same thing, since $b = -w \cdot \text{location}$). The step goes up if $v$ is positive and down if $v$ is negative.
  • By location we mean the center of the step: the point where the curve is steepest, half way between its two flat levels. (For the ReLU blocks of chapter 1 the location is the point where the ramp bends.)
  • A note on location vs bias, because they are easy to mix up. The network itself stores a bias $b$ (the weight on the gray edge from the constant-1 node), and the node computes $\phi(w x + b)$. The center of the step is where $w x + b = 0$, that is, at $x = -b/w$; this is what we call the location. So the two are linked by $b = -w \cdot \text{location}$, but they are different numbers: for hidden node 1 below, $w_1 = 2.0$ and location $= -2.0$, so $b = -(2.0) \cdot (-2.0) = +4.0$. The slider uses the location because that is what you see on the plot; the diagram shows the bias because that is what the network stores.
  • Add three steps with different locations, directions, and heights, and we get a non-linear function like the one below.
  • Parameter count: 3 per block plus the output bias $c$, so 10 in total (chapter 1's two-block network had 7, and linear regression had 2). Each extra block contributes one more step to the sum and adds 3 more parameters.
  • Let's see if you can recover the parameter values we used: adjust the nine sliders until the sum passes through the middle of the data points. Note that the loss cannot reach zero now (the points are noisy), but it can get as low as the noise allows, and it gets there exactly when your blocks match the generating ones!

2. Now Let Gradient Descent Turn the Sliders

  • Press reset and then train, and watch the sliders: they move on their own!
  • What's happening under the hood is a loop, repeated thousands of times:
    1. Predict: compute the sum of the blocks at every data point.
    2. Compare: measure the loss (MSE) between the sum and the data points.
    3. Adjust: adjust every parameter a small amount in the direction that lowers the loss. The direction comes from the gradient of the loss (more on how it's computed in a later chapter), and the amount we adjust each iteration is controlled by the learning rate (here 0.25).
  • One pass through all the data points is called an epoch. Watch the epoch counter: the loss falls quickly at first, and then progress slows down (the last few decimals take most of the epochs).
  • Let's compare the two buttons directly. Press fit (reveal the answer) and note the loss. Now press reset, then train, and let all the epochs finish. The trained loss is lower than the loss of the true generating parameters!
  • How can training beat the truth? Because the loss only measures the fit to these noisy points. The generating parameters are the best description of the underlying function; the trained parameters are the best fit to this particular noisy sample. They are answers to two different questions.
  • Note that the final parameters from training end up close to the generating ones, but not exactly on them, and the final loss is slightly below the loss of the generating parameters. With noisy data, the generating parameters are no longer the ones with the lowest loss: the extra epochs go into fitting a little bit of the noise itself. (This effect is called overfitting; much more on it in a later chapter.)
  • After training finishes, drag the replay slider to move back and forth through the epochs and watch the whole story again at your own pace.
  • Try the noise slider too. With the noise at zero, training and the generating parameters agree exactly. The more noise you add, the further the trained parameters drift from the generating ones.
  • You can also grab a slider in the middle of training (training pauses when you do). Try moving one block far away and pressing train again: gradient descent fixes it!

(Optional) The Same Network in Code

  • Everything on this page is a 1 → 3 → 1 network. Here it is in numpy, forward pass first:
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

h = sigmoid(np.outer(x, w) + b)      # three hidden activations   (n, 3)
y_hat = h @ v + c                    # output: sum of the blocks
loss  = np.mean((y_hat - y) ** 2)    # MSE, the loss you watched above
  • And a vectorized version of the same training loop (predict, compare, adjust):
lr = 0.25
n = len(x)

# starting values for the parameters (matching the demo's reset button)
w = np.array([1.0, 1.0, 1.0])    # slopes
b = np.array([3.0, 0.0, -3.0])   # biases (= -w * location)
v = np.array([0.3, -0.3, 0.3])   # heights
c = 0.0                          # output bias

for epoch in range(400_000):
    h = sigmoid(np.outer(x, w) + b)
    err = h @ v + c - y
    grad_h = np.outer(err, v) * h * (1 - h)    # chain rule through the sigmoid
    v -= lr * 2/n * (h.T @ err)                # adjust every parameter
    c -= lr * 2/n * err.sum()
    w -= lr * 2/n * (grad_h * x[:, None]).sum(axis=0)
    b -= lr * 2/n * grad_h.sum(axis=0)
  • (One small difference from the demo above: on this page $c$ is set automatically, while in the code we simply let gradient descent update $c$ like every other parameter. Both work.)
  • The same model and loop in PyTorch. Note that loss.backward() computes all the gradients for us (no chain rule by hand):
model = nn.Sequential(
    nn.Linear(1, 3),   # x -> three hidden nodes   (the w's and b's)
    nn.Sigmoid(),      # the activation
    nn.Linear(3, 1),   # sum of the blocks         (the v's and c)
)
criterion = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.25)

for epoch in range(400_000):
    optimizer.zero_grad()
    loss = criterion(model(X).flatten(), y)
    loss.backward()
    optimizer.step()
  • (PyTorch initializes the parameters randomly, so its path down the loss will differ from the demo's; the destination is the same.)

Chapter Highlights

  1. A sum of three sigmoid blocks can fit data generated by three sigmoids, as well as the noise allows.
  2. Each block has a location, a slope, and a height; fitting the data comes down to choosing these nine numbers well.
  3. Gradient descent is the predict, compare, adjust loop; an epoch is one pass through the data.
  4. The loss falls quickly at first and slowly at the end.
  5. What you did by hand with nine sliders, gradient descent does automatically (and it scales to millions of parameters).
